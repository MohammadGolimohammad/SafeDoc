# SafeDoc
قفل سخت‌افزاری با اثر انگشت و حافظهٔ داخلی؛ برنامهٔ مدیریت Windows Forms با .NET Framework 4.8.

## اجرای نرم‌افزار

پروژهٔ فعال رابط کاربری، SafeDoc.UI است. Startup Project را در Visual Studio روی همین پروژه بگذارید و SafeDoc.slnx را بسازید. دستگاه با VID_CAFE و PID_4014، سرعت 115200 و تنظیمات 8N1 شناسایی می‌شود.

قبل از اجرای برنامه، اتصال همان پورت را در HTerm یا نرم‌افزارهای سریال دیگر ببندید. هنگام انتظار پاسخ، پنجره پاسخ‌گو می‌ماند و عملیات دستگاه به ترتیب اجرا می‌شوند. پس از خطای ارتباط، دکمهٔ «اتصال دوباره» برای ایجاد ارتباط تازه در دسترس است.

## سازگاری با HEX ارائه‌شده

رابط کاربری فعلی برای همان firmware با فرمان‌های ۱ تا ۲۰ تنظیم شده است. کاربران با فرمان ۲۰ از ده جایگاه جداگانه خوانده می‌شوند؛ فرمان ۱۹ به دلیل بافر محدود پاسخ تجمیعی در HEX، در راه‌اندازی این نسخه استفاده نمی‌شود. بین فرمان‌ها ۱۱۰۰ میلی‌ثانیه برای پایان پردازش firmware فاصله گذاشته می‌شود.

ثبت کاربر ابتدا اثر انگشت را ثبت می‌کند، سپس رمز و انقضا را روی دستگاه ذخیره می‌کند. ویرایش اطلاعات، اثر انگشت قبلی را حفظ می‌کند. در صورت شکست جایگزینی رمز، برنامه برای بازگرداندن رمز قبلی تلاش می‌کند و شکست بازگردانی را گزارش می‌دهد. فهرست کاربران فقط پس از خواندن کامل جایگزین می‌شود.

گزینهٔ «بدون انقضا» مقدار timestamp صفر را ارسال می‌کند. مجوز فلش برای هر کاربر در HEX فعلی پشتیبانی نمی‌شود و کنترل آن غیرفعال است؛ وضعیت ساختگی در تنظیمات محلی ذخیره نمی‌شود. نام رمز باید در ده بایت UTF-8 و رمز در بیست نویسهٔ قابل چاپ ASCII جا شود. در firmware فعلی نقل‌قول و بک‌اسلش در نام و رمز پذیرفته نمی‌شود، چون پاسخ firmware آن‌ها را escape نمی‌کند.

لایهٔ Business همچنین APIهای محافظت‌شدهٔ فرمان‌های ۲۱ تا ۲۶ سند جدید را دارد؛ استفاده از آن‌ها به تشخیص صریح firmware دارای پشتیبانی نیاز دارد. رابط کاربری برای HEX تأییدشده، فرمان‌های جدید را در راه‌اندازی ارسال نمی‌کند. فایل HEX تغییر یا پروگرام نشده است.

## بررسی تغییرات

در PowerShell از ریشهٔ پروژه:

~~~powershell
.\tests\Run-RegressionChecks.ps1
~~~

این دستور پروژه را در build-verification می‌سازد و آزمون‌های شبیه‌سازی پروتکل و حلقهٔ پیام Windows Forms را اجرا می‌کند. آزمون‌ها به دستگاه فرمان نمی‌فرستند. موارد شامل پاسخ تکه‌تکه، timeout، لغو، بسته شدن فرم، پاسخ دیررس، ترتیب فرمان‌ها، خواندن کاربران، ذخیرهٔ واقعی از مسیر دکمه و حفظ اثر انگشت در ویرایش است. برای ساخت، Visual Studio یا Build Tools و targeting pack نسخهٔ .NET Framework 4.8 لازم است.
